## 1. Fix springdoc-openapi — Swagger UI returned 500

**File:** `backend/pom.xml`

`springdoc-openapi-starter-webmvc-ui` was pinned to `2.6.0`, incompatible
with `spring-boot-starter-parent 3.5.0` (Spring Framework 6.2 removed the
`ControllerAdviceBean(Object)` constructor that springdoc 2.6.0 still calls
→ `NoSuchMethodError` on any request to `/v3/api-docs`).

```diff
  <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
- <version>2.6.0</version>
+ <version>2.8.9</version>
```

The bug was already present on `origin/main` (commit `edc78fc`) — not a
local environment issue. Full details in `BUGFIX-springdoc-openapi.md`.

**Verified:** `/api/v3/api-docs` → 200, Swagger UI loads.

## 2. TICKET-ADV042 — Missing counterparty trade

**Goal:** an internal trade with no external counterpart must produce a
`ReconResult` with status `BREAK` and `discrepancyType = "MISSING_EXTERNAL"`.

### `backend/src/test/java/com/dbtraining/reconx/service/ReconciliationEngineTest.java`

Implemented `testReconcile_missingCounterpartyTrade_returnsBreak` (given/when/then):
- given: one internal `EquityTrade`, empty external list
- when: `engine.reconcile(List.of(internal), List.of(), ReconciliationRule.EXACT)`
- then: `status == BREAK` and `discrepancyType == "MISSING_EXTERNAL"`

### `backend/src/main/java/com/dbtraining/reconx/service/ReconciliationEngine.java`

Two changes were needed for the test to pass:

1. **Guard in `reconcile(...)`** used to short-circuit whenever `external`
   was empty too, so `matchOne` never even ran for the BREAK case. The
   guard now only checks `internal`; a `null` `external` is coerced to an
   empty list instead.

2. **`matchOne(...)`** — added the branch for `external == null`, returning
   `ReconResult.breakResult(internal.tradeRef().value(), "MISSING_EXTERNAL", null)`.
   The price/quantity comparison branch (for MATCHED, ADV040/041) is left
   untouched — a teammate is working on it in the same file.

**Verified:** `./mvnw test -Dtest=ReconciliationEngineTest#testReconcile_missingCounterpartyTrade_returnsBreak`
→ `Tests run: 1, Failures: 0, Errors: 0`, `BUILD SUCCESS`.

## 3. TICKET-ADV043 — Mockito ArgumentCaptor

**Goal:** using `ArgumentCaptor<ReconResult>`, assert on the *content* of
the object passed to `repository.save(...)`, not just that it was called.

### New files created

- `backend/src/main/java/com/dbtraining/reconx/repository/ReconResultRepository.java`
  — a plain interface (`ReconResult save(ReconResult result)`), not JPA,
  since `ReconResult` is a record/DTO, not a persisted entity.
- `backend/src/main/java/com/dbtraining/reconx/service/ReconciliationService.java`
  — wraps the existing `ReconciliationEngine` + `ReconResultRepository`;
  `runRecon(...)` calls `engine.reconcile(...)` and saves each `ReconResult`
  via `repo.save(...)`.
- `backend/src/test/java/com/dbtraining/reconx/service/ReconciliationServiceTest.java`
  — mocks `ReconResultRepository`, uses `ArgumentCaptor<ReconResult>`,
  `verify(repo).save(captor.capture())`, asserts on `tradeRef()` and `status()`.

### Decision: BREAK test scenario instead of MATCHED

The ticket's reference solution tests a **MATCHED** scenario (identical
trades). We used a **BREAK** scenario (`MISSING_EXTERNAL`) instead.

**Why:** the MATCHED branch of `ReconciliationEngine.matchOne(...)` depends
on `priceQty(...)`, which is still `throw new UnsupportedOperationException(...)`
— a teammate is implementing it as part of ADV040/041, in parallel, in the
same file. Testing MATCHED now would fail because of someone else's
unfinished code, not ours. The BREAK scenario exercises the `external ==
null` branch of `matchOne`, already implemented and green as of ADV042 — so
the ADV043 test verifies exactly what it needs to (capture + assert on 2
fields) without depending on another teammate's unfinished ticket.

**Verified:** `./mvnw test -Dtest=ReconciliationServiceTest`
→ `Tests run: 1, Failures: 0, Errors: 0`, `BUILD SUCCESS`.
